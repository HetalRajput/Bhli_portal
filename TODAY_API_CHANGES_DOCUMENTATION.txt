TODAY APIs DOCUMENTATION
========================

Base URL examples below use:
https://bhli-backend.onrender.com

Local example:
http://127.0.0.1:8000

Auth:
- Public APIs do not require token.
- User booking APIs require user JWT token unless mentioned as public.
- CRM APIs require CRM/admin JWT token:
  Authorization: Bearer <access_token>

Response Pattern:
Most APIs return:
{
  "success": true,
  "message": "Optional message",
  "data": {}
}

Paginated list APIs return:
{
  "success": true,
  "count": 100,
  "next": null,
  "previous": null,
  "page": 1,
  "page_size": 20,
  "total_pages": 5,
  "data": []
}


1. Airport Search API
---------------------

URL:
GET /api/base/airports/

Purpose:
Frontend can search airport/city data for flight booking.

Payload:
Not required.

Filters:
- search: optional, searches airport code, name, city, country
- code: optional, exact airport code, example DEL
- city: optional
- country: optional
- page: optional
- page_size: optional

Example:
GET /api/base/airports/?search=delhi&page=1&page_size=20

Response:
{
  "success": true,
  "count": 1,
  "next": null,
  "previous": null,
  "page": 1,
  "page_size": 20,
  "total_pages": 1,
  "data": [
    {
      "id": 1,
      "airport_id": 1001,
      "airport_code": "DEL",

      "airport_city": "Delhi",
      "airport_country": "India",

}

7. Vendor URL Tracking API
--------------------------

URL:
GET /api/base/vendors/<vendor_link_slug>/url/

Example:
GET /api/base/vendors/example-vendor-flight/url/?utm_source=homepage

Purpose:
Frontend calls this API first. Backend saves click tracking data and returns the final vendor URL. Frontend redirects user to data.url.

Payload:
Not required.

Optional Query Params:
Any query params can be sent. Backend stores them in request_query_params.

Backend Captures:
- logged-in user if Authorization token is sent
- IP address
- user agent
- referrer
- session key
- request query params
- UTM values
- destination URL/final URL
- click_id

Response:
{
  "success": true,
  "message": "Vendor URL generated successfully.",
  "data": {
    "url": "https://vendor.example.com/flights?utm_source=bhli&utm_medium=referral&utm_campaign=flight-booking",
    "vendor_name": "Example Vendor",
    "slug": "example-vendor-flight",
    "click_id": 25
  }
}

- rating: optional rating 1-5
- page: optional
- page_size: optional

      "id": 1,

12. Booking APIs - Common Rules
-------------------------------

All typed booking APIs below require user token.

Common Required Payload:
{
  "service": 1
}

Common Optional Payload:
{
  "service_item": 10,
  "message": "Optional customer message",
  "consent_to_contact": true,
  "guests": [
    {
      "name": "Guest One",
      "age": 30,
      "gender": "male"
    }
  ]
}

Notes:
- service must match the selected endpoint slug.
- service_item is required only when service.requires_service_item is true or booking_mode is items.
- message is optional and common for all services.
- user/profile fields are fetched from JWT/profile where applicable; frontend should not send user email, department, employee id, pay level etc. unless a specific detail model asks for it.

Common Response:
{
  "success": true,
  "message": "Booking request submitted successfully.",
  "data": {
    "id": 1,
    "booking": {
      "id": 100,
      "user": 12,

  "check_in_date": "2026-09-10",
  "check_out_date": "2026-09-12",
  "number_of_rooms": 1,

    "adults": [
      {
        "name": "Adult One",
        "age": 35,

}

Optional Payload:
{
  "check_in_time": "12:00:00",

- guests must be grouped as adults and children.
