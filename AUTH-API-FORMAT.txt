Authentication API Format

1) Route: POST /api/auth/send-otp
   Purpose: Send a one-time password to the user email for login.
   Method: POST
   Request headers:
     Content-Type: application/json
   Request payload:
     {
       "email": "user@gmail.com"
     }
   Response payload:
     {
       "success": true,
       "message": "OTP sent successfully."
     }
   Error response payload:
     {
       "success": false,
       "message": "Please enter a valid Gmail address."
     }
   Notes: Used by src/app/login/page.tsx when the user submits the login email.

2) Route: POST /api/auth/verify-otp
   Purpose: Verify the OTP and authenticate the user.
   Method: POST
   Request headers:
     Content-Type: application/json
   Request payload:
     {
       "email": "user@gmail.com",
       "otp": "123456"
     }
   Response payload:
     {
       "success": true,
       "message": "OTP verified successfully."
     }
   Error response payload:
     {
       "success": false,
       "message": "OTP verification failed."
     }
   Notes: Used by src/app/login/page.tsx after the user enters the 6-digit OTP.

3) Route: POST /api/auth/register
   Purpose: Register a new user account for website access.
   Method: POST
   Request headers:
     Content-Type: application/json
   Request payload:
     {
       "firstName": "John",
       "lastName": "Doe",
       "mobile": "9999999999",
       "serviceNumber": "IC-XXXXX",    // optional
       "otp": "123456"                 // if registration uses OTP verification
     }
   Response payload:
     {
       "success": true,
       "message": "Account created successfully."
     }
   Error response payload:
     {
       "success": false,
       "message": "Unable to register the user."
     }
   Notes: The current registration page at src/app/register/page.tsx does not yet call an API. This endpoint should be integrated there.

4) Route: POST /api/auth/logout
   Purpose: End the user session and clear authentication state.
   Method: POST
   Request headers:
     Content-Type: application/json
   Request payload:
     {}
   Response payload:
     {
       "success": true,
       "message": "Logged out successfully."
     }
   Notes: Optional but recommended for proper session handling.

5) Route: GET /api/auth/me
   Purpose: Get the current authenticated user details.
   Method: GET
   Request headers:
     Authorization: Bearer <token>   // optional if using token-based auth
   Response payload:
     {
       "success": true,
       "user": {
         "email": "user@gmail.com",
         "firstName": "John",
         "lastName": "Doe",
         "mobile": "9999999999"
       }
     }
   Error response payload:
     {
       "success": false,
       "message": "User not authenticated."
     }
   Notes: Useful for protecting pages and displaying the logged-in user.

6) Route: POST /api/auth/refresh-token
   Purpose: Refresh authentication tokens if using JWT refresh flow.
   Method: POST
   Request headers:
     Content-Type: application/json
   Request payload:
     {
       "refreshToken": "..."
     }
   Response payload:
     {
       "success": true,
       "accessToken": "...",
       "refreshToken": "..."
     }
   Notes: Optional and only required if implementing token refresh.

General API integration notes:
- All auth endpoints should use JSON for request and response bodies.
- The login flow currently uses localStorage under key "bhli-auth" to mark authenticated users.
- If you add server-side authentication, update the login and registration pages to store session tokens or cookies.
- The website needs at least send-otp and verify-otp for login, and register for new account creation.
